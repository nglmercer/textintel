# Speech number lexicons

`numbers.json` is embedded, versioned lexical data for the speech number
verbalizer. It is not a model and has no inference/runtime dependency.

## Sources and preparation

- The initial en/es/zh/hi/ar/fr/pt/ru/id/de/ja/tr/ta/vi/ko standalone 0–99
  words and contextual hundred/thousand prefixes were prepared with ICU
  **78.3**, whose RBNF data derives from **Unicode CLDR 48.0** (confirmed
  using `ulocdata_getCLDRVersion`). Primary rule
  files: <https://github.com/unicode-org/cldr/tree/release-48/common/rbnf>.
  The Unicode License V3 notice is included in `LICENSE-UNICODE.txt`.
- Marathi 0–99 labels are adapted from the BSD-licensed
  [libnumbertext mr.sor](https://github.com/Numbertext/libnumbertext/blob/73d0bb4bb8106a0f2f6d7b68ec1727b249e9299f/data/mr.sor),
  attributed there to Ankur Joshi. The upstream BSD notice is retained in
  `LICENSE-NUMBERTEXT.txt`. Word facts are not trained parameters.
- Bengali, Urdu, Punjabi (Gurmukhi), and Telugu are curated lexical tables;
  no external formatter is used at runtime. They need broader native-speaker
  review before a production pronunciation claim.
- The initial CLDR output was deliberately reviewed rather than trusted as a
  speech oracle: discretionary German soft hyphens were removed; Chinese
  zero is 零; Japanese uses explicit kana readings; Arabic uses standalone
  nominative dual forms; Tamil linking stems and hundred/thousand compounds
  are explicit. Region/case/inflection variants are not silently claimed.

Preparation uses ICU's `RuleBasedNumberFormat(URBNF_SPELLOUT, Locale(code))`
for integers 0–99, and 100n/100n+1/100n+10/1000n/1000n+1 for n=1..9.
Those outputs initialize `small`, exact hundreds/thousands, and nonzero
prefixes. The corrections above and the curated locales are then applied.
The checked-in JSON is the authoritative input; builds do not fetch or
regenerate it. Tests validate resource shape and independently specified
spoken gold cases, not merely values generated by this preparation process.

## Explicit support

- All 20 locales support digit reading and exact decimal fractions, preserving
  signs and zeroes, with at most 128 digits per integer/fraction component.
- ar/ta/te standalone cardinals cover 0..9,999.
- hi/bn/ur/pa/mr cover 0..999,999,999 using lakh/crore grouping.
- en/es/zh/fr/pt/ru/id/de/ja/tr/vi/ko cover 0..999,999,999,999.
- es/pt/ru feminine integer forms are separately available only through 999.
  They do not replace the grammar needed for arbitrary currency/counter nouns.
- Larger, malformed, or leading-zero cardinal inputs return unsupported;
  leading-zero identifiers can explicitly request digit reading.

Representative choices are general Spanish, US-style English without
optional "and", French as used in France, Brazilian Portuguese large scales,
Simplified Chinese, Punjabi Gurmukhi, and Sino-Korean. Locale-base support
must not be mistaken for every regional pronunciation, dialect, grammatical
case, currency agreement, or an independent native-speaker accuracy audit.

See the Unicode [RBNF scope and limitations](https://unicode.org/reports/tr35/tr35-numbers.html#Rule-Based_Number_Formatting):
number spellout data alone does not supply the grammatical context required
for agreement in a sentence. The parser and verbalizer expose unsupported
cases instead of inventing that context.

## Composition audit

A development audit compared all integers 0..9,999 plus selected supported
scale boundaries and maximum values against ICU 78.3 / CLDR 48.0: 140,225
comparisons across en/es/zh/hi/ar/fr/pt/ru/id/de/tr/ta/vi/ko. Comparison removed
German soft hyphens, normalized Unicode NFC, and equated Chinese 〇 with 零.
This checks composition against the table source; it is not an independent
linguistic accuracy measurement. Generated reference rows are not shipped as
gold tests.

The audit found and fixed Spanish apocope before scale nouns, Korean 일 before
억, and Vietnamese lẻ after a million-scale group. Representative regressions
are retained in `tests/speech_numbers.rs`. en/es/hi/fr/pt/ru/id/de/tr/vi/ko had
no remaining reference differences in the audited samples. Arabic matched
after the documented spelling and nominative-dual corrections; the raw ICU
comparison differs for 1,900 of its 10,000 samples.

Chinese has one unresolved style difference in the larger samples:
1,001,001,001 is rendered 十亿零一百万一千零一 here, while ICU emits
十亿一百万一千〇一. A fluent reviewer should decide the desired gap-zero
convention. Tamil differs from raw ICU in 9,966 of 10,000 samples because the
explicit compound/linking-stem corrections affect most compounds; raw ICU is
therefore not an accuracy oracle for that locale. Japanese kana readings and
the curated bn/ur/pa/mr/te tables require separate pronunciation and composition
review. Supported ranges describe implemented bounds, not native-speaker
certification of every value in those bounds.
